# איך סקריפטים משתמשים בספרייה

## המיקום

הסקריפטים של הרכיבים שבשירות (ההקמה, בונה הפלייבוק, הנושא ונותן, המנסח, מעריך הסיכונים, מרשם ההתחייבויות) והספרייה המשותפת מגיעים בחבילה אחת, `areo-runtime.zip`, ונפרסים בתיקייה זמנית של המחשב (`AREO_RT`):

- `AREO_RT/lib`: הספרייה (`common`, `orchestrator`, `playbook`, `risk`, `obligations`).
- `AREO_RT/skills/<מזהה הרכיב>/scripts`: הסקריפטים של כל רכיב.

ספרייה אחת משרתת את כל הרכיבים, ואין עותק שלה בתוך רכיב.

## איך סקריפט מייבא מהספרייה

כל סקריפט מייבא קודם את `areo_lib.py` שבתיקיית הסקריפטים שלו (קובץ זהה בכל רכיב), שמוסיף את `AREO_RT/lib` לנתיב הייבוא, ואחר כך מייבא מהספרייה:

```python
import os, sys
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
import areo_lib  # noqa: F401  מוסיף את AREO_RT/lib לנתיב הייבוא

from common.paths import long_path   # noqa: E402
```

## כללים

- קוד של רכיב יושב ב-`scripts` של הרכיב ומייבא מהספרייה; הספרייה אינה מייבאת מרכיב.
- נקודת כניסה של מודול משתמשת ב-`common.cli` (argparse, `--out` מפורש, קובץ קלט אינו נדרס) ואינה כותבת `__pycache__` לתוך החבילה.
- יציאה לרשת רק דרך `common.net.fetch`; מקור רגולטורי רק מ-`מקורות-מאושרים.json` (`risk.validate_register.approved_domains`, בלי רשימת נפילה); כתובת פסיקה נדחית תמיד (`common.case_law`).
- רכיבים שהסקריפטים שלהם עדיין בתוסף (המתרגם, האסטרטג) אינם מייבאים מהספרייה בזמן ריצה, ומחזיקים בדיקה מקומית מינימלית. המנסח מאתר את הספרייה דרך `areo_rt.py` (AREO_RT, ואחריו מיקום הסקריפט בחבילה).
- רשימת המקורות המאושרים אינה נטענת להקשר של המודל: `common/approved_sources.py` (וב-CLI `research_sources.py lookup`, `market_research.py lookup`) מחזיר את הרשומה של כתובת אחת בלבד.
