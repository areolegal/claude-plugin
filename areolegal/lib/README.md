# קוד ייחוס להערות לניל (סבב 3)

מימוש ייחוס שמצורף להערות, בנפרד מהקבצים של ניל. הקוד מראה איך לממש את שורות "דורש התאמה בקוד אצל ניל", ובכל שורה כזו בהערות כתוב "מימוש ייחוס: קוד-ייחוס\<הנתיב>". הוא אינו מחליף את הקבצים של ניל, ואינו נוגע בהם.

**סביבה:** Python 3, ספריית התקן, python-docx ו-lxml בלבד.

**הרצת הבדיקות:** `python -m pytest קוד-ייחוס\tests -q`. הבדיקות משתמשות רק בקבצים הקטנים שב-`tests\fixtures\`, ואינן קוראות מתיקיות של לקוחות.

**חוזה הלולאה לפני משלוח (מתואם עם מעריך הסיכונים 3.6).** המרשם: `<תיקיית העסקה>\risk-register.json`. השורות: `pre_send_fixes[]`, לכל שורה `id` ("PSF-01"), `kind` (`missing`, `incomplete`, `created_by_response`, `polish`), `gap`, `where`, `risk_ids`, `clause_ref` (clause_id של סעיף בהסכם, מפתח ב-`numbering_map`; לעולם לא מזהה כלל) ו-`status`: `open` (מעריך הסיכונים כותב תמיד `open`, ואינו כותב בקובץ המצב), `resolved` או `conceded` (רק הנושא ונותן). `resolution`: `{"how": "reopened", "decision_id", "at"}` או `{"how": "deliberate_concession", "at"}`. סגירה בפתיחה מחדש: הכרעה עם `reopened_from_fix: <id>` ב-`clauses[]` של קובץ המצב. סגירה בוויתור: רשומה ב-`deliberate_concessions[]` עם אותו `clause_ref`, `from_pre_send_fix: <id>`, `user_decision` (`answer_kind`, `answer`, `recorded_at`), `crosses_red_line`, `gap_codes` ו-`report_as: accepted_risk`. שורת `polish` אינה חוסמת.

**בדיקה מול Word עצמו (אופציונלית):** כש-`AREO_WORD_CHECK=1`, הבדיקה `test_word_accept_reject_match_projection` פותחת את קובץ העבודה ב-Word (דרך `tests\word_views.ps1`), מריצה שם "קבל הכול" ו"דחה הכול", ומשווה להטלה של המנוע, אחרי נרמול של מעבר שורה בתוך פסקה. בלי המשתנה היא מדולגת.

**היגיינת אריזה:** כדי שהרצת הבדיקות לא תכתוב `__pycache__` לתוך החבילה, להריץ עם `python -B -m pytest קוד-ייחוס\tests -q -p no:cacheprovider`. נקודות הכניסה עצמן (`python risk\extract_corpus.py ...`) אינן כותבות `__pycache__` (גרסה 1.2.0).
